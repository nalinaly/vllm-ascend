核占用/24＝所有 worker 的 kernel-duration-us 之和除以 24，**不是整段延迟**。
点2列为单 worker mean，不能直接与其他行的核占用相加。DFX每个版本是独立单次采样，
只用于定位核内和相邻任务，不能代替同进程 ABBA 的完整设备跨度。
点1的核内实现没有丢弃：完整补丁、编译记录、泳道与两档数值证据都保留。
但点1＋3的组合在长档五组全部回退，按用户后续的 8:2 口径，不将该组合设为默认。

## 口径与环境

- A3，CANN 9.2.0-beta.2；固定 `DeepSeek-V4-Flash-0731-w8a8` 的第3层真实权重。
- BF16 残差、NZ mode=2、atomic=0、deterministic=0；无 EPLB。
- PTO 两侧均 `torch.compile(backend="npugraph_ex", dynamic=False)`，inplace pass、static compile 开，superkernel 关。
- 单卡、同进程 ABBA 五组，每侧10个设备跨度；表中均为 μs，顺序为 **min / max / mean**。
- B4仅一组功能与窄行检查，不能用于性能判断。8K/B16用于点1/2/5，8K/B24用于点3/4及组合。
- 每个点只与自己的同窗控制比较。点4控制是点3；“新调度上的K-shift”控制是同样关闭提前调度的非K-shift。
- 不把不同进程、时间窗或版本的收益相加；这轮没有重新测 Native、七档整网或生成 token。

## 第二点重新审视：保留调度联动候选

只关闭 O-A producer 的 `allow_early_resolve`，阻止其量化消费者提前占用执行资源；
原有数据依赖、四处/八组交接和算术保持原样。没有全局加 sync_start 或删除真实依赖。
K-shift 本身仍按 `((outer + pa_unit) % K段数) * 段宽` 循环读取，改变 FP32 累加顺序。

| 配对 / 档位 | 控制 min / max / mean | 候选 min / max / mean | 均值变化 | 改善组数 |
| --- | --- | --- | --- | --- |
| 只关闭 O-A 提前调度 / 128K B16 | 562.500 / 616.750 / 576.375 | 566.000 / 586.750 / 574.975 | -0.243% | 3/5 |
| 相同新调度：无K-shift → 有K-shift / 128K B16 | 559.500 / 602.000 / 575.275 | 559.250 / 574.500 / 565.975 | -1.617% | 5/5 |
| 相同新调度：无K-shift → 有K-shift / 8K B16 | 458.750 / 476.500 / 466.325 | 446.500 / 471.750 / 458.050 | -1.775% | 5/5 |

新调度下长短档五组配对均改善，8:2加权 −1.648%。这个结果足以保留候选，
不能沿用此前“只因一次 DFX 变慢就放弃”的结论。
但是它**不是同窗四方因子试验**：不能把上表前后两行相加，也不能证明收益一定来自交互项。

独立 DFX 的矛盾仍保留：新调度下加入 K-shift，O-A worker mean 24.105→27.328 μs，
O-A执行包络78.68→89.42 μs；因此尚不能把整段改善解释成 O-A 核内更快。
原先独立 DFX 中未修改的前段任务也变快，整段与分段不能跨时间窗强行归因。

精度状态：128K/B16 的 x_out 有212/1572864元素不同，max_abs=0.015625，
RMSE=2.93918e-5；8K/B16有369个元素不同，max_abs=0.015625，RMSE=4.21231e-05。
无非有限值，cache/state逐bit、同版本重放和保护区通过；短档补位通过。
这些只是算术差异诊断，**独立逐元素参考、整模型逐token和DSpark统计仍待验收**。
所以完整候选留下，但本轮不设默认，不把非零差异写成“精度通过”。

## Native源码依据与实现限制

以本地 `ops-nn`、CANN 9.2的A3实现为依据，不把arch35路径当A3，不声称源码推导等于当前安装二进制的逐项tiling。

1. O-A：`ops-nn/matmul/transpose_batch_mat_mul/op_kernel/transpose_batch_mat_mul.cpp` 的NZ分派及 `MM_CFG_K_SHIFT`；
   host的 `CalcBaseMN`、`TuneBaseMKN`、`DoCommonTiling` 得到 M96/N256/K64、stepKa8/stepKb4。
   对应Mat448KiB、L0A24KiB、L0B64KiB、Acc96KiB。PP einsum仅是ND策略参考。
2. K-shift：CANN `matmul/scheduler/iterator/k_loop/k_loop_mdl_reorder.h:57–84`。
   Native按物理block编号，PTO这里按SPMD任务编号；映射不同，不能宣称调度完全一致。
3. Q-B：A3 `quant_batch_matmul_v3_pertoken_opt.h` 的 MDL 配置，以及CANN `scheduler_mdl_base.h` 的 CopyIn / SplitA / SplitB。
   原N256/K256的L0B只有一个64KiB槽；新L0 K128生成0/32768两个地址。
   N256、M128、四组各4个Cube worker、依赖和后处理不变；INT8→INT32累加不引入浮点重排。
4. A复用：CANN `copy_cube_in_mdl_base.h` / `copy_cube_in_mdl_fullload.h` 的A侧驻留与缓存命中。
   仅在点3新流水上试，不原样重测旧N128/K256失败候选。
5. Q-A：`ops-nn/matmul/mat_mul_v3/op_host/op_tiling/matmul_v3_base_tiling.cpp` 的NT CalcBase / CalBaseMBaseN / CalL1Tiling / UpdateL1TilingStepK。
   推导M96/N48/K128、22块、A-K512/B-K1024；最后一块有效N16；不臆造FullLoad适用。
   NZ L1的转置采用 `pl.tile.transpose_view`，不复制设备权重；实际结果仍比起点慢。

O-A/Q-B显式窄行Acc依赖当前PyPTO内部 `compact=True`，不能当作稳定公共接口；
已通过窄行和补位验证。编译过程中必要的SSA、自由维度、constexpr调用表达修复，
均限于候选算子，没有修改PyPTO、Simpler、PTOAS、PTO-ISA或Native主流程。
默认改动只有HCA的 `q_projection_streamed.py`；CSA、精度入口及cache布局不变。
