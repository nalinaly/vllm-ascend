# Cache写回：保持逐行搬运的有效分工

基底为e110a886，KV第二项的N64候选未混入；BF16残差、CANN9.2、mode2/atomic0/det0。
私有包完整复制并冻结，先验证两根依赖图、CPU编译及生成核，再通过task-submit自动排队上卡。

## 分工与流水检查

原版8个worker轮流承担8-token块：T96中四核16行、四核8行；T144中两核24行、六核16行。
改为每worker最多ceil(T/48)行，实际worker数ceil(T/每worker行数)，不产生空worker或padding计算。
T96为48×2，T144为48×3；小T不足48时只启动有效worker；尾部继续min保护。

- wb48：只改变外层token分工。
- wb48_sync：在相同分工上单独增加sync_start=True，组大小不超过48 AIV。

保留物理1×512 BF16搬运、两项slot标量读取、page/offset非负保护、原地址及写回依赖。
原版并无多token双缓冲，不能把缩短串行token循环称为削掉了stage2流水。
生成码三版本均一处TLOAD、一处TSTORE、无TMOV，相同1×512 Tile与MTE2/MTE3事件序列；
只是原两层token循环合为一层。静态一致不能替代真实并发带宽检查，结果另测。

最新本地ops-transformer 28f40354的scatter_pa_kv_cache_tiling.cpp::DoNoCompressOpTiling
同样按ceil(numTokens/usedCoreNum)再计算有效核数；kernel ProcessFullyLoad保留负slot跳过及逐token搬运。
只借鉴有效任务分配，不声称Native CSA实际选择了这一源码模板。

## 并发边界

KV第二项baseline首窗中：长档写回166.88–179.46μs，与Attention Compressor/Q_B/Indexer Q的AIC任务重叠；
该窗口没有其他AIV任务重叠。短档写回203.12–216.12μs，与scatter_softmax_pool及boundary_init重叠。
这些是执行区间相交，不是同一物理核同时执行的证明。
Compressor pool按请求沿时间顺序更新state，不能仅为填核拆成无依赖的token并行；
因此本项先观察写回占满48 AIV后对pool的影响，不顺手全开邻居sync。
