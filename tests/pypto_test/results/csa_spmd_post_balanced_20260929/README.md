## 分工与流水检查

- 原每worker处理最多4个token：128K/B16有24个worker，8K/B24有36个worker。
- 新每worker处理`ceil(T/48)`个token，worker数为`ceil(T/ceil(T/48))`。
  T96时每worker2个token、T144时3个token，两档均48个worker；T24只用24个有实际工作的worker。
- 单token物理tile仍为`1×4096`，8组INT32部分和反量化次序不变，BF16舍入位置不变。
- 四条HC残差的加载、片上复用及加法次序不变；没有新增临时GM搬运、规约或padding计算。
- 只调整原最外层token循环范围，不改变内部算术、缓存策略及buffer形状；先查编译产物，再看真实核时确认流水没有退化。
- sync候选只对这个已均衡的48-worker任务设置sync_start，保留真实O-B前置依赖与原early标志。
  O-B以及量化前驱仍按原分工，若观察到资源竞争再单列联动候选，不先扩大修改。
