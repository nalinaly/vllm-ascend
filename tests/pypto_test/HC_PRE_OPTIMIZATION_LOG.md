# 独立 HC_pre：30 μs 优化过程

## 最新已验证状态（2026-10-10）

正式入口已采用 `cv_shape_dispatch_v4.py`：单个动态 JIT 入口，完整计算在同文件 inline 函数中，
按 T≤32、33～48、49～96、T>96 选择分块。各分支使用单个 SPMD、屏障后双 AIV 分工及 pre/post 八列合并。
源码只导入 `pypto.language`，不复用 CSA/HCA 或 pypto-lib 中的计算函数。

验证链为 v3 全量十四场景加 v4 四个大形状增量场景；未改分支生成的计算体已直接比对一致。
前四场景的 L1 三次采样均低于 30 μs；最新 T168 首尾中位数及最大值均为 39.96 μs，完整目标尚未达成。
L4 另按对应 v3/v4 快照补采十四场景，全部通过固定数值、图重放、换输入和保护行检查。
两个版本、不同轮次及 L1/L4 的计时分别保留，不将汇总数据写成同一次全量执行。

本轮优化建立在已推送的完整搬运提交 `a257be63` 上。仓库内证据入口：
[候选与运行报告](results/hc_pre_opt_20261009/README.md)、
[十四场景 AscendC/L1/L4 下载目录副本](results/hc_pre_profiles_20261010/README.md)。
以下各节按试验发生时间保留，当时的“当前”“正在验证”不覆盖本节最新状态。

## 目标与冻结口径

- 保持独立 `vllm_ascend/ops/pypto/hc_pre.py`，所有计算均在本文件，不引用 CSA/HCA 算法。
- B=2/4/8/16/20/24/28 × S=5/6，共十四场景，T=B×S=10～168；相同 T 的不同 B/S 分别验证。
- 完整 HC_pre，包括设备内转换、RMS、投影、门控、20 次 Sinkhorn 和混合，三份输出都要通过原门禁。
- PTO 使用 L1 泳道的 incore 首尾跨度；目标是十四场景三次采样均低于 30 μs，不用执行并集替代首尾。
- 数值门禁、graph/eager、同址换输入和保护行检查不放宽。三步 PyTorch profiling 与泳道一并保留。
- 当前未达标，不以局部阶段、少数形状、仅编译成功或旧采样代替目标验收。

## 指定 AscendC 基线

参考 [上游 HcPre kernel](https://gitcode.com/cann/cann-recipes-infer/tree/master/ops/ascendc/src/hc_pre/op_kernel)
及 [mHC 优化说明](https://gitcode.com/cann/cann-recipes-infer/blob/master/docs/models/deepseek_v4/deepseek_v4_mHC_guide.md)。
本次下载的 master 为 `4c3d1e1258053c4d810322198a7fd1722c89897e`，本地只读源码在工作区
`.cache/hc-pre-recipes-20261009/`，不修改其中的算子实现。

A3 实现分两阶段：转换与 Cube 计算通过 workspace 形成 CV 流水；Cube 同时生成投影和平方和，
向量阶段归约、门控、混合与 Sinkhorn，尽量提前搬入残差。指南中的历史性能不能替代当前机器实测。

现有 release 包与最新上游并非同一份源码：最新 HcPre 增加可选 `pre_mix` 输入及 `pre` 输出。
因此单独用上游 `build.sh -n hc_pre -c ascend910_93` 构建包，并直接编译上游
`npu_hc_pre.cpp`、`ops_common.cpp`；测试目录只提供两个接口的 schema 注册和 CPU 构建脚本。
实际调用 `custom::npu_hc_pre`，走融合 `aclnnHcPre`，`pre_mix=None`、`pre_out=None`，三份输出与 PTO 对齐。
上游 `npu_hc_pre_v2` 现在返回四份输出，不能与旧 release 的同名接口混用。

测试默认 `--native-backend recipes`，要求显式传 `--native-library` 与 `--native-opp`。
进程初始化前选择独立包，并在首次调用后从进程映射确认加载的 `libcust_opapi.so` 路径。
旧包只能显式指定 `--native-backend release`，用于历史追溯，不再作为目标验收基线。
没有安装或覆盖共享 PyPTO、Simpler、vLLM Ascend 或 CANN 包。

上游基线任务 `task_20261009_223444_241933515055` 已 exit=0，B2/S6 与 B28/S6 全部功能、精度检查通过。
Native HcPre 三次中位数为 38.04 / 75.66 μs；对应当时 `wide.py` PTO 为 32.48 / 72.26 μs。

## 正在验证的方向

`bf16_pair.py`：保留 FP32 权重接口，在算子内分成 BF16 高、低两部分，两次投影合并；
BF16 残差直接进入 Cube，平方和从分段 Gram 矩阵对角线获得，消除整份残差 FP32 加宽缓冲和独立 RMS 任务。
这会改变浮点归约和权重的内部表示，必须先通过原数值门禁，再判断性能。尚未记录 PASS 或达标。

失败的 CPU 尝试也保留报告：单行 row_sum 不满足 A3 列向量 32B 对齐；int32 xor 和 int16→int32 直接 cast 不受当前路径支持。
仅修改本仓库候选表达方式解决，没有修改编译器或运行时。
